## GitHub Actions pipeline contract
### 1. Untrusted PR checks — no deploy credentials
Trigger `pull_request` on every PR update, trusted default-branch push, and a scheduled daily full dependency/secret scan (schedule is a future workflow proposal, not a routine created here). Avoid required-check path filters that silently skip security jobs; docs-only changes may skip build through a checked decision, but an always-running final gate reports actual results.

Global token `permissions: contents: read`; job permissions only when needed. Set checkout `persist-credentials:false`; history depth sufficient for secret/diff scans. Disable write tokens and all cloud/DB/model secrets for PR/fork jobs. **Never** use `pull_request_target` or privileged `workflow_run` to check out/execute untrusted PR code. Do not interpolate PR titles/branch text into shell commands. Dependabot PRs are untrusted for secrets too. No self-hosted runner processing arbitrary PRs; prefer fresh hosted Linux runners within approved entitlement.

Required named jobs (names finalised once and required by protection):
1. **install-quality** — verify Node/npm version + lockfile; `npm ci`, formatting/lint/strict typecheck, production build. Dependency install must not change lockfile; unexplained multiple package-manager locks fail. Check built public bundle/source maps for forbidden privileged keys and accidental research/fixture assets; source maps private or disabled in prod.
2. **unit-contract** — Vitest pricing/matching, schema validation, result-state precedence, PTA branch boundaries and capability/idempotency state machine. No real provider calls or sensitive fixtures. Core security and numeric boundaries explicitly tested, not a superficial coverage percentage.
3. **dependency-security** — audit complete dependency tree + OSV lockfile scan. Retain redacted machine-readable output≤7d with scanner/database timestamps and triage context. Scan errors/network unavailability fail the gate; do not turn “no report” into zero findings. Use a reviewed cached advisory snapshot only if fresh≤24h, else block merge or obtain documented temporary exception.
4. **sast-security** — Semgrep OSS with checked-in pinned rules (JS/TS injection, XSS, secrets misuse, insecure crypto, SSRF, path/SQL/template injection) + small Kitne Ka rules for unsafe HTML, arbitrary fetch destinations and privileged client env variables. Treat rule pack changes as security-sensitive. Optional entitled CodeQL in addition, not assumed.
5. **secret-security** — gitleaks with redaction, PR commit range and built artifact scan; full-history initial/default scheduled scan. No raw secrets in annotations/artifacts. Use deliberately fake fixture credentials and verify detector rejects them in a dedicated test; never use a live secret as a test canary.
6. **db-security** — ephemeral local Supabase/Postgres migrations from empty DB, repeat/upgrade compatibility, explicit RLS/grants tests as anon/authenticated/runtime/migrator roles. Test Worker-level capabilities separately: service-role success is not an RLS test. No public write of evidence/policy; storage private/disabled.
7. **security-contract-e2e** — bounded Playwright core paths with synthetic fixtures and provider/network mocks: screenshot redaction, upload rejection, restricted/unknown URL zero-fetch, XSS/model injection, cross-session IDOR, revoke/expiry HTML+PNG, no PII logs/PWA, classify no remote calls, duplicate/cancel/offline replay and quota races. Use local runtime by default; deployed egress/CPU smoke separately required before path enablement.
8. **required-gate** — always runs, inspects all applicable jobs and fails if any required job fails/cancels/is unexpectedly skipped. Do not use `continue-on-error` for scanners or hide failures in piped shell output.

Use concurrency per PR to cancel superseded check runs, job timeouts (initial proposal10min each/20min E2E, tune from measured durations), bounded artifact retention≤7d and no payload/screenshot artifacts from real users. Synthetic labelled screenshots in test artifacts only. Cache package download directories by OS/runtime/lock hash, never secrets/`.env`/untrusted build outputs across trust boundaries. Deploy job cannot consume executable artifacts/caches produced by an untrusted fork.

### 2. Workflow supply-chain controls
- Pin **every external Action to a full immutable commit SHA**, with reviewed version comment; pin container images by digest and CLI versions with verified checksum. Do not invent SHAs in this plan; resolve/verify before workflow merge. Dependabot proposes controlled updates, never silent floating `@main`/`@vX` for trusted deployment.
- Dedicated CODEOWNERS coverage for `.github/`, dependency/lock files, Wrangler configuration, DB/RLS/migrations, extraction/network boundaries and share renderer. All pipeline changes require SecOps review; domain/source-policy changes CTO review. Avoid adding new security SaaS/code upload by default.
- Minimal GITHUB_TOKEN: read-only for ordinary checks; `security-events:write` only in an entitled report-upload job on a trusted context if needed; `id-token:write` only for a selected deploy job when provider federation is actually supported/configured. Never blanket `write-all`. Prefer short-lived scoped deploy credentials; if no supported OIDC path, protected environment-scoped API token with least privilege/rotation.
- No privileged token in build-time `VITE_*`, caches, step output or public env file. Runtime secrets via Wrangler secret bindings. Preview/prod Gemini/DB/deploy identities separate; migration/admin role unavailable to runtime. Protect operator accounts with MFA; maintain owner/rotation inventory without key values.

## Merge/release thresholds
**Proposed strict initial baseline; fix before merging, not “launch later” debt.** An exception is specific, recorded with finding ID/CVE/rule, scope, compensating control, independent reviewer and expiry≤7d or G4 (whichever earlier), and does not invent legal/vendor permission.

| Gate | Blocks merge / enabled-path launch |
|---|---|
| Quality/tests | Any failed install, lint/type/build, migration, required contract/security test or unexpected skipped check. No lockfile drift. |
| Secrets | **Any real credential/private key** anywhere in history/change/built output. Revoke/rotate immediately, then remediate; deleting a line is insufficient. False-positive allowlist needs rule/path-specific reviewed rationale, never blanket regex ignores. A real active secret cannot be waived. |
| Dependencies | Any unresolved Critical/High advisory in direct/transitive **production or build chain**, or any known exploited/reachable vulnerability regardless of score. Unknown severity/reachability triaged before merge. Medium/Low non-exploitable findings may proceed only with owner/expiry≤14d; a Medium on auth, uploads, SSRF, data leakage or CI privilege is blocking until fixed or independently shown inapplicable. No blanket devDependency exclusion; build/install scripts can execute secrets-bearing code. |
| SAST | Any new untriaged finding; any confirmed High/Critical or exploitable finding; Medium in sensitive boundaries blocks. Reviewed demonstrable false positives allowed narrowly. Existing baseline cannot hide confirmed launch blockers. |
| Access/privacy | Any cross-session access, direct anon private-row access, public evidence write, PII in logs/share/cache, missing expiry/revoke/delete, unsafe HTML, source-policy bypass or outbound request on denied URL. No waiver for active disclosure; disable affected path. |
| Spend | Duplicate paid invocation under concurrency/replay, bypassable global cap, uncontrolled retry or missing approved vendor/privacy/audience/cost status blocks fallback enablement. |
| Release chain | Unreviewed/pinned-action drift, privileged secrets in PR jobs, preview prod binding, absent independent review or unproven rollback route blocks release. |

At G4: **zero unresolved Critical/High or known exploitable vulnerabilities on enabled paths**, zero real leaked credentials, all ten [threat-model launch blockers](threat-model-v1.md) evidenced or explicitly contained by disabled paths. New finding since freeze still blocks; feature freeze is not a security exemption. Founder may approve scope removal/cost choices, not override vendor terms or falsely label an unsafe feature secure. SecOps+CTO document residual risk and alternatives; Founder owns launch decision.

### Branch/review enforcement
Protect default/release branches: PR-only changes, ≥1 independent authorised reviewer (not author), CODEOWNER review on sensitive paths, dismiss stale approvals, require latest push review, all required named checks current against base, resolved conversations, no force-push/deletion/direct push, protections apply to admins where supported. Require two independent reviews for CI/secrets/RLS/network/public-sharing changes when team capacity permits; minimum one non-author security-qualified review cannot disappear to meet deadline. Multiple bots acting as the same account do not create independent human approval.

[GitHub protected branch behaviour](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) checked9 Nov2026 PKT. Verify private-repo plan supports actual protections and deployment approvals; plan not inspected. If unavailable, Founder chooses an approved eligible plan or a documented restricted-deployer/reviewed-release compensating process; **do not claim merge protection exists**, and do not make code public merely to unlock free scanning. Break-glass narrowly named, logged and retrospective; no routine bypass of failed security tests.

## Preview environments — real isolation, not URL naming
**Recommended minimum:** one dedicated non-production Worker/Wrangler environment + **separate Supabase preview project**; production has its own Worker/config, database project and secrets. CLI-local ephemeral DB for each PR test, one serialised shared integration preview for approved branches. Shared preview deploys use concurrency lock/commit banner; avoid migration races. Per-PR persistent DBs are not needed for the14-day sprint.

A Cloudflare **Version URL (formerly preview URL)** runs that version's **existing bindings/resources**, not an automatically isolated environment. A production version URL can therefore expose production DB/provider keys. Disable public production version URLs unless specifically reviewed; use a separately configured preview Worker/environment for test URLs. Cloudflare's newer PR Previews are distinct; verify isolation, support for every binding, account availability, teardown and billing before adoption. No assumption that any URL with “preview” is safe.

Preview rules:
- Never clone/copy production/user/licensed datasets into preview; synthetic fixtures labelled, no fabricated “live market” evidence. Separate DB keys, project IDs, storage policy, rate namespaces, signing keys, source registry and Turnstile keys/hostnames. Remote extraction and external source adapters disabled; approved synthetic-only provider checks separately metered if specifically approved.
- Validate expected project/Worker/env ID before migrations and startup; fail on production identifiers in preview. No inheriting prod Wrangler bindings/secrets by omission. Prod service-role key never granted to preview or fork code.
- Access-restrict integration preview using approved Cloudflare Access or equivalent reviewed protection; noindex is not access control. Free/paid entitlement and identity setup need approval. Public synthetic-only previews still expose code attack surfaces and can consume resources: per-environment quotas/expiry required.
- Untrusted PR only builds/tests without secrets. Preview deployment from a trusted workflow definition after a reviewer approves the **exact commit**; reapproval on updates. Environment credentials apply only to isolated non-production resources. Do not check out fork code inside a prod-privileged job. If protected environment approvals unavailable on plan, use approved deployer procedure rather than a privileged auto-PR workflow.
- Remove per-PR Workers/aliases/branch resources on merge/close, or proposed TTL≤48h after last approved deploy; separate trusted cleanup path cannot execute PR code. Shared preview reset with migration+synthetic seed, not production copy. Audit orphan resources/cost daily during sprint.

## Deploy and rollback outline (future authorised execution)
1. Engineer prepares small reviewed PR with migrations/config changes and tested disabled-by-default feature flags. All checks and security review pass. Build release from trusted reviewed commit with lockfile; record commit, artifact digest, scanner versions, policy/methodology version and environment identifiers. Do not promote untrusted PR artifacts to prod.
2. Deploy same reviewed commit/artifact to isolated integration preview; run synthetic smoke, two-session access denial, uploads/type limits, denied URL no-fetch, PII sink check, snapshot revoke/expiry, idempotency/quota concurrency and deletion-job smoke. Measure **real Worker** parser/PNG CPU/memory and deployed egress where enabled. Local tests alone cannot validate edge runtime security.
3. Verify Founder approvals: vendor/spend/privacy/audience/source rights and actual release scope. Check deployment secrets scoped, managed logs omit payloads, cron enabled, cap/kill switches and alerts active. Confirm recoverable backup/restore route appropriate to chosen plan; no automatic assumption free backups exist.
4. Use **expand/contract migrations** compatible with old+new Worker version. Narrow migrator identity, explicit expected DB project check, one deployment at a time. Add columns/tables first; destructive drops/rewrites deferred beyond rollback window or require separate approval and verified recovery. DB migration success is not implied by a Worker rollback.
5. Approved deployer releases to production through protected trusted job/environment; record prior Worker version, new version, schema migration and config/secret revisions. Disable risky adapters/model by default and enable only reviewed cleared paths. Gradual deployment only if chosen plan/runtime supports it; don't invent a canary deployment.
6. Post-release bounded synthetic checks: shell/API health, real RLS deny, source/status correctness, share HTML/PNG, expiry/cleanup, cost ledger and errors. Monitor first30min plus ongoing daily review; no real-user screenshots in smoke. Any cross-session/PII leak, quota bypass, duplicate paid call, unsafe source fetch or sustained error spike triggers containment; provisional reliability trigger >5%5xx for5min after minimum20 dynamic requests, tune after measurements. Critical security trigger needs no traffic threshold.
7. **Contain first**: disable model/source/publish path, revoke compromised credentials where needed; approved deployer returns to recorded known-good Worker version/config. Secrets/bindings/data/schema are separate rollback concerns. Prefer forward-compatible DB repair; never automatically down-migrate/drop production data. Re-test health/RLS/privacy/caps; no blanket replay of uncertain paid operations. SecOps records incident and coordinates Founder decision via approved channel (none sent here).
8. Before G4, exercise rollback+restore in preview with synthetic data and record commands/results/version IDs, time-to-restore and residuals. Target app rollback≤15min is a proposal to prove, not an SLA claim. After restoring any backup, replay expiry/deletion/revocation before exposure. Store runbook in app docs, without secrets.
