# Pricing methodology v0 — deterministic, evidence first
Owner CTO. Date 9 Nov 2026 PKT. **Initial assumptions to calibrate, not empirically validated thresholds.** Aligned with parent/PM v0 steering: 3 minimum; 5+ and 2 sources for normal confidence; 14/30-day freshness; median; -15%/+10%; P10–P90. No implementation or test success claimed.

## 1. Product identity and hard matching
Canonical Product = category ID + brand + model family + manufacturer model/part number where known. Variant = versioned category-config attribute schema; store normalised values and raw evidence, not a single concatenated title. Alias dictionaries handle punctuation, spelling, Roman Urdu and manufacturer naming. Fuzzy text/LLM suggestions generate candidates ONLY; explicit manufacturer/variant attributes determine admission. LLM cannot supply missing prices/specs/PTA status or infer condition from a model name. User confirms ambiguous required fields; extraction confidence is per field, not evidence confidence.

| Category | Hard comparable attributes (unknown target → ask; unknown candidate → exclude) |
|---|---|
| Phones | Exact model/generation, storage, RAM when variable, manufacturer region/model when radio/SIM/warranty differs, factory unlocked vs carrier/JV locked, **PTA approved vs non-PTA** (never merge; unknown target uses separate exploratory branches below), sealed/new vs used; local/international/no warranty separately |
| Laptops | Manufacturer part/SKU or equivalent exact CPU generation/model, GPU/VRAM, RAM, SSD capacity/type, display size/spec tier, new vs used, warranty; same marketing name is insufficient |
| Consoles | Generation/revision, disc vs digital, storage, edition, new vs used, standard controller/accessory bundle, warranty; no cross-pooling PS5 Slim/original/Pro or altered/jailbroken hardware |

Used grade: like_new / good / fair; repaired, refurbished, open-box, kit-only, damaged, battery-defective and unknown-grade are separate/unpriced in v0 unless PM explicitly defines a matching pool. For used phones collect battery health band (>=90, 80–89, <80) where relevant and repair status. Unknown price-driving used attributes cause insufficient evidence/confirmation, not invented depreciation. Optional colour may pool only when category config explicitly allows; region, PTA and condition never silently pooled. City is optional display/filter; initially Pakistan-wide pool with geographic warning, not unsupported city-adjusted valuation.

Exclude accessories-only, deposits/monthly instalments, “starting from”, missing/zero/negative prices, auctions without fixed ask, out-of-stock/cancelled, stale/undated, foreign currency/import-exclusive offers, VAT/tax ambiguity, personal coupon/card-only promotions, conflicting variant claims, bundles that cannot be exactly compared. Use unconditional advertised cash price inclusive of mandatory taxes; record delivery separately and compare product-only prices consistently. If compulsory charges are unknown, exclude rather than pretend landed totals match. Official MSRP is a distinct anchor, not a current offer unless verified in stock at that price.

## 2. Provenance, independence, deduplication
Each PriceObservation stores listing ID/canonical URL, seller identity hash/independence group, source method + licence ID, source_updated_at/observed_at/retrieved_at, PKR integer minor units (paisa), full attributes, stock, capture evidence hash and verification state. A new fetch timestamp must not refresh an old offer’s market-observation timestamp. An undated user image is target-only. Search snippet retrieval is index retrieval, not merchant observation; cannot count as a fresh price without licenced source verification.

Deduplicate same listing across requests, syndicated listings across domains/APIs and cross-posted seller offers. Use latest verified observation per seller+variant+condition; one effective comparable per independent seller in the pool. Multiple search API routes to one merchant are not source diversity. Target asking price is never an observation in its own benchmark. Independent sources = distinct underlying owner-controlled commercial sources, not URLs. Multiple independent sellers on one marketplace can increase sample size, but not the underlying platform-diversity count. User uploads unverified for seller/time do not count. Counts report before/after every exclusion.

## 3. Freshness
Hard expiry: new **14 × 24 hours**, used **30 × 24 hours**, measured from verified observed_at/source_updated_at as applicable, never merely HTTP fetched_at. Boundary exactly 14/30 days admitted; older excluded. Future dates/quasi-fresh snippets excluded. Prefer collection refresh every 24 hours new and 72 hours used if permission allows; API/cache expires earlier when source licence requires it. Official-retail anchor verified within 14 days, labelled “verified retail” with source/date; otherwise null (historic MSRP not a live retail value). Expiry of any included observation invalidates derived cache. No stale-while-revalidate price verdict after hard expiry.

## 4. Range calculation, outliers and minimum evidence
1. Partition by canonical variant + condition/grade + PTA/lock/warranty policy; calculate new and used separately. Never use a new pool to fill a used gap.
2. Apply permission, availability, matching, freshness, independence and dedup filters.
3. If initial n >= 8, calculate Q1/Q3 with linear-interpolated quantiles (`h=(n−1)p`). Remove strict values outside `[Q1−1.5 IQR, Q3+1.5 IQR]`; log `STATISTICAL_OUTLIER`. If IQR=0, do not auto-trim; flag spread anomalies for review. For n<8 no statistical trimming, only factual exclusions. This is “trimmed comparables” via IQR, not repeatedly trimming P10/P90 tails.
4. After filtering: **n<3 → INSUFFICIENT_DATA**, no range/median/verdict/difference for selected pool. Ambiguous critical identity, unverifiable source rights, or final `(max−min)/median >0.60` also suppress assessment and request review; wide-spread threshold is initial conservative policy.
5. n=3–4 → min–max and LOW confidence. n>=5 → P10–P90 of the filtered pool (same quantile definition). Anchor = median of filtered values (mean of middle two if even). It is an **asking-market estimate**, not completed-transaction value, not a probabilistic confidence interval.
6. New/used may each be null independently. A verified-retail single anchor may be shown separately even if a pool is insufficient, but never rendered as a market range or used to create a verdict.
7. Cache and persist methodology_version, config_version, input observation IDs + exclusions and source-policy version so an assessment is reproducible. Round only display; compare exact minor-unit values/rational thresholds before rounding.

## 5. Verdict and explanation
For asking price A and valid selected-pool median M, `delta_pct=100*(A−M)/M`.
- **FAIR**: `−15 <= delta_pct <= +10` (inclusive).
- **HIGH**: `delta_pct > +10`.
- **UNUSUALLY_LOW**: `delta_pct < −15`, always “Verify condition, PTA/lock status and seller before paying”; not an accusation of fraud.
- **INSUFFICIENT_DATA** overrides everything when selected-pool evidence fails, including when asking price absent.
- **NO_ASKING_PRICE** when evidence passes but A is null; show market range and “Add the asking price to get a verdict”, differences null.

Asymmetric initial bands recognise downside condition/misdescription risk and common asking-price negotiation. These are policy assumptions, not a market truth. The UX’s “midpoint” must mean **median anchor**, not arithmetic `(range_low+range_high)/2`, which can differ. Label it “market median” in explanatory copy and provide both separately if a graphical midpoint is wanted. LOW-confidence results retain enum but `indicative=true`, subdued “Indicative: …” label and concrete reasons; no hard recommendation. Absence of a target price is not a zero price. Unknown PTA asks for confirmation but does not block a check; it returns separately labelled exploratory pools under §9, never a guessed tax deduction or mixed median.

## 6. Confidence formula
Not a calibrated probability of correctness. Compute only after evidence gates, values clamped 0..1:
- `S=min(n/10,1)` sample adequacy, n effective independent seller observations after filters.
- `D=min(d/3,1)` independent source-owner diversity.
- `R=mean(1−0.5*age_days/freshness_window)` recency; eligible observations range 0.5..1.
- `Q=mean(match_quality)`; exact manufacturer SKU + confirmed critical fields =1.0; verified equivalent attributes + reviewed aliases =0.9. A critical mismatch/unknown is excluded, not discounted into admission; target PTA uncertainty is the explicit branch-routing exception in §9, not permission to admit unknown-PTA evidence.
- `C_raw=round(100*(0.30*S+0.25*D+0.25*R+0.20*Q))`.
- Cap at **49** if n<5 OR d<2; cap at **79** if `(P90−P10)/M >0.30` or an included observation has identity quality <1.0. Cap at 49 for unverified geographic heterogeneity materially affecting comparable interpretation; otherwise warning. For insufficient result score=null, level=NONE (not false precision). For unconfirmed target PTA, cap every displayed branch at49 and add PTA_UNCONFIRMED; do not compute a blended score/median.
- LOW 0–49, MEDIUM 50–79, HIGH 80–100. “Normal confidence” requires n>=5 AND d>=2; score may still be lower for quality. Reasons are structured enums: FEW_COMPARABLES, SINGLE_SOURCE, NEAR_EXPIRY, WIDE_SPREAD, ATTRIBUTE_MATCH_NOT_SKU, GEOGRAPHIC_MIX, ASKING_NOT_SOLD_PRICES. Show sample size and newest/oldest observation dates.

## 7. Illustrative numeric example — invented example data, NOT live prices
A fictitious exact phone variant, sealed/new, PTA-approved, same warranty; five independent merchants across three owner-controlled sources; verified observations ages 1,2,3,4,5 days. Example cash prices PKR **98,000; 100,000; 102,000; 104,000; 106,000**. A sixth non-PTA offer at 85,000 is excluded (VARIANT_MISMATCH); target at 115,000 excluded from benchmark by definition.

n=5; no statistical trimming for small n. Median M=102,000. Linear P10=98,800; P90=105,200. A=115,000; difference +13,000; delta=12.7451% → **HIGH**. Fair band is 86,700 through 112,200; strictly below 86,700 Unusually Low. Range endpoints are not verdict thresholds. R=1−0.5*(3/14)=0.892857; S=.5, D=1, Q=1; C=round(100*(.15+.25+.223214+.2))=82 → HIGH confidence, still only asking-price evidence. If two comparables expire, n=3: range min–max, confidence capped LOW; if another expires n=2: no estimate. With valid evidence and no A: NO_ASKING_PRICE. Used-market range and verified-retail anchor remain null if no independent eligible evidence exists.

## 9. Revision: PTA uncertainty, state precedence and classify-only (9 Nov 2026 PKT)
Reviewed UI/UX `d2-ia-and-flows.md` in full and PM `prd-v0.2.md`. This section replaces any earlier implication that target PTA uncertainty blocks all results. Product policy recommendations remain assumptions pending G1 ratification.

### Missing PTA does not block Check
Ask Approved / Non-PTA / Not sure. Missing/skipped answer normalises to `NOT_SURE`; model, condition and other required category attributes still require confirmation. This aligns the user's non-blocking preference while avoiding a falsely low blended market median. The Designer's “Not sure widens matching” means **search both known-PTA branches independently**, never mix prices. Unknown-PTA candidate listings remain excluded. JV/CPID/carrier lock remain separate price-driving attributes; do not mislabel them simply as non-PTA.

Run APPROVED and NON_PTA separately, each against the same other confirmed attributes and each requiring its own n>=3, permission, freshness and spread gates. Return zero, one or two labelled ranges, with branch-specific n, sources, dates and exclusions. **n=2 approved + n=2 non-PTA is insufficient**, not n=4. If either branch passes, RANGE_AVAILABLE in PTA_SPLIT mode; display only passing branches, explain any missing branch. If neither passes, INSUFFICIENT_DATA. Each displayed branch forced LOW (score capped49), reason PTA_UNCONFIRMED, even if it has abundant evidence. There is no merged median, aggregate range or global price verdict. With a supplied asking price the verdict slot is `PTA_SELECTION_REQUIRED`; with no price PTA selection still precedes price verdict. Prompt “Confirm PTA status to get a verdict”; optionally show the separate ranges, not “Fair” against both. Confirming PTA selects the corresponding retained branch, rechecks validity, removes uncertainty cap and computes against that branch only. No need to refetch if its snapshot is still valid. Do not show a different PTA branch as the user's valuation.

### Exact Low vs Insufficient boundary
Insufficiency is an **evidence/identity gate, not a confidence-score cutoff**. A branch needs n>=3 after all filters, confirmed critical attributes other than target PTA handled above, permitted/verified provenance, non-expired evidence and `(max−min)/median <=0.60`. If a gate fails: no branch range, score=null, level=NONE, specific insufficient reasons. If gates pass, LOW is integer score0–49 inclusive, MEDIUM50–79, HIGH80–100. Score0 does not itself mean insufficient. n3–4 or only one underlying independent source caps score49; normal confidence additionally needs n>=5 and d>=2. Other caps in §6 still apply. Statistical/spread thresholds are provisional, not empirically validated.

### Result-state precedence
1. **ERROR**: an operation cannot evaluate evidence because required service/DB failed, timed out or input validation failed. No market verdict; retry/edit preserves inputs. A genuine completed collection with no offers is not Error. Partial provider failure may still permit a result if valid cached/remaining evidence was successfully evaluated; attach warnings and apply gates honestly. Never turn complete source-service outage into a fabricated “no data” finding.
2. **INSUFFICIENT_DATA**: completed evaluation but no applicable branch passes evidence gates; no headline numbers, no verdict, confidence NONE. Suppresses low-confidence modifier.
3. **RANGE_AVAILABLE**: at least one applicable branch passes. Selected known-PTA pool has FAIR/HIGH/UNUSUALLY_LOW if asking price supplied; otherwise NO_ASKING_PRICE. Unknown PTA uses PTA_SPLIT and PTA_SELECTION_REQUIRED with verdict=null. LOW confidence is an independent modifier on range layouts, including no-price/split layouts, not a fourth result state.

### Lightweight classify-only operation
`POST /checks/{id}/classify` accepts asking price and optional confirmed `pta_status`; uses stored immutable comparable snapshot and **median**, not `(range_low+range_high)/2`. No source API, OCR, LLM or new evidence collection. Recheck permission revocations, config/methodology validity and observation validity before calculating. Reject with409 RANGE_STALE when `now > valid_until`, where valid_until is earliest included observation's observed_at +14 days new/30 days used (or earlier contractual expiry); exactly at boundary passes. If policy/config/source invalidated:409 EVIDENCE_INVALIDATED. If no retained qualifying range or PTA still unselected:422 NO_STORED_RANGE / PTA_SELECTION_REQUIRED. Requires full new assessment for refresh; do not silently start one or incur spend. Updating price does not refresh evidence dates or valid_until. Confidence recency may be recomputed from the same stored observations; range/median/n do not change. Return a new private classification version, preserve original check time and immutable public snapshots. Repeat same request/idempotency key returns same version. Tests specified, not run.
