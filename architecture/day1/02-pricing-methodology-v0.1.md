## 2. Lean records and independence (Q5/Q19)
`Money={amount_minor:integer paisa,currency:'PKR'}`. Lean `PriceObservation`: id,listing_id,price,observed_at?,source_updated_at?,retrieved_at,provenance_ref. **ComparableCandidate**, constructed from Listing+observation, carries sellerOwnerId, canonicalListingId, inStock, city, variantMatch{matched,exclusion_reason,quality}, source/permission/provenance and comparable cash-price basis. No seller identity/contact information inferred from OCR.

Resolve **ultimate commercial seller owner**, not seller display-name string, through licensed source metadata/verified curator registry. Same owner across shops/domains/APIs is one owner. Unknown/unverified identity cannot fabricate diversity: UNVERIFIED_PROVENANCE, not a new synthetic owner per row. API host/platform owner is recorded for provenance but **not the independent-source counter**. One licensed API can expose multiple independently verified merchant owners; count them separately. Multiple platforms under one company do not force d=1 if underlying sellers are independent; multiple seller fronts under one ultimate owner do.

Deduplicate canonical/cross-posted listing first, then retain one latest otherwise-eligible offer per sellerOwnerId+canonical target variant+condition branch. Latest means greatest effective_timestamp; ties greatest retrieved_at, then lexical canonicalListingId and observation id ascending (stable, not input order). Missing ownership cannot be treated as unique. `n` effective offers after filters/dedupe/trim; `d` distinct included sellerOwnerId. With one offer/owner this normally yields n=d in integrated pools; retain n/d parameters and existing caps for scorer unit tests/backward compatibility. **Old FIL-08 platform-owner rule intentionally changes.** Correlated single transport/feed availability remains a provenance/coverage risk, not unapproved fabricated merchant diversity.

## 3. Money, normalisation and asking-price errors (Q2/Q7/Q23)
Parse **decimal strings**, not binary float/parsing by parseFloat or removal of arbitrary characters. Recognise existing PRD numeric notations: Rs/Rs./PKR/₨, Western/lakh commas after validating grouping, optional trailing /-, k/K=1,000, lac/lakh/L=100,000, crore=10,000,000. Case-insensitive existing suffixes; do not infer lakh from bare decimal. Extra numeral scripts/plural/compound Roman Urdu scope awaits PM/Founder (see09). Bounded input length/precision, no scientific notation/arbitrary extra tokens. Multiple price tokens→candidates+requires_confirmation, never silently pick final/cheapest. Instalment/deposit/per-month/starting-from excluded upstream PRICE_NOT_COMPARABLE; target EMI-only asks for full PKR cash price, may proceed with null ask for range.

Convert exact decimal PKR×multiplier×100 to rational paisa; round sub-paisa **half-even** once into observation/asking Money. Reject NaN/Infinity as NON_FINITE, empty/unparseable as NOT_A_NUMBER, literal zero ZERO, negative NEGATIVE; **positive amount rounding to0 paisa → ZERO**, not TOO_SMALL. Numeric minimum1paisa/maximum9,007,199,254,740,991paisa are technical representation bounds only, not plausible market bounds. Out-of-bound positive→TOO_SMALL/TOO_LARGE; reject beyond supported safe Money representation before numeric conversion. Category plausibility min/max must be approved config; no invented PKR1,000 universal floor. Valid decimal preview may exist while market-use plausibility config unresolved; fail closed for candidate admission if required config missing, CONFIGURATION_REQUIRED error (503,not an invented valuation). User target below configured plausibility bounds needs correction/confirmation; do not auto-convert to null or invent multiplier. Domain/PM must ratify actual bounds at G1; no guessed limits in this methodology.

POST/assessments and /classify require positive safe integer amount_minor when supplied: zero/negative/noninteger/out-of-bounds→**422 INVALID_ASKING_PRICE**, retryable=false, errors.price.invalid. Null alone means no asking price; classify permits explicit null asking price with a confirmed PTA selection; at least one input field (asking_price, including explicit null, or confirmed PTA) must be provided, subject selected-branch rules, per API v0.5. Malformed outer JSON/type→400 INVALID_REQUEST. No verdict computed for invalid input. Normaliser errors remain detailed ZERO/NEGATIVE/etc; API maps validation error without treating zero as absent.

## 4. Freshness and injected clock (Q4/Q10/Q22)
Parse RFC3339 instants at millisecond precision. If either provided timestamp invalid/unparseable, or **either raw timestamp >now+300,000ms**, exclude INVALID_TIMESTAMP, even if the other is old/valid. Exactly300s future skew allowed. Effective timestamp=min(observed_at,source_updated_at) if both; if updated null use observed; if observed null but updated exists use updated; both null/missing→UNDATED. retrieved_at never refreshes market age.

`age_ms=max(0,now−effective_timestamp)`; `age_days=age_ms/86,400,000` (fractional, no day truncation). New admitted age<=14×24h, used<=30×24h, exactly inclusive; beyond→STALE. Future accepted skew contributes age0. now=checked_at for evaluation, classified_at for classify recency recompute. Source permissions/contracts may expire earlier. Freshness rule and RANGE_STALE use same effective timestamps/window. Private record TTL is separate and stricter if already expired; expired private check410 even if observations fresh. Proposed refresh cadence24h new/72h used, within permissions; no stale estimate after hard expiry.

## 5. Primary exclusion precedence and provenance (Q8)
Each candidate has exactly **one primary exclusion**, tested in this order; aggregate counts in this order and retain secondary diagnostics only internally without double counting:
1 TARGET_LISTING;2 UNVERIFIED_RIGHTS (missing/expired/disallowed collection/display rights);3 UNSUPPORTED_CURRENCY;4 PRICE_NOT_COMPARABLE (non-positive/invalid money, EMI/deposit/monthly/starting-from/conditional-only/unknown compulsory tax);5 NOT_IN_STOCK (false/unknown);6 UNKNOWN_CRITICAL_ATTRIBUTE;7 CONDITION_MISMATCH;8 VARIANT_MISMATCH;9 INVALID_TIMESTAMP;10 UNDATED;11 STALE;12 UNVERIFIED_PROVENANCE (seller/time/source verification);13 DUPLICATE;14 STATISTICAL_OUTLIER (post-match/stat pass).

Timestamp validator internally checks invalid/future before undated/stale; prior primary failures still win. Unknown candidate PTA→UNKNOWN_CRITICAL_ATTRIBUTE; known other PTA→VARIANT_MISMATCH. No invalid candidate admitted just to satisfy counts. Availability must be affirmed, cash price inclusive mandatory taxes, delivery separate consistent basis. Rights-cleared public merchant URLs/dates only; private target URL is not shared evidence. List source retrieval and market effective dates separately.

## 6. Deterministic range pipeline and spread decisions (Q1/Q20)
Permission/match/availability/timestamp/provenance filters → deterministic dedupe → **single IQR pass if pre-trim n>=8** → final evidence/spread gates → stats → confidence/caps → verdict. Quantiles use sorted exact integer paisa with `h=(n−1)p`, linear interpolation; median p=.5, even median mean of middle two.

IQR Q1/Q3 over admitted pre-trim pool, fences Q1−1.5IQR/Q3+1.5IQR; exclude **strictly** outside. Fence equality stays. No repeated trimming after exclusions or recomputation of fences. IQR=0: no auto-trim; if max>min emit warning `IQR_ZERO_SPREAD_REVIEW`; if all identical no anomaly warning. No independent penalty/block from that flag; final spread gate still applies.

After IQR, n<3→Insufficient, no range/median/verdict, confidence NONE/null. Final **(max−min)/exact median >0.60**→EXCESSIVE_SPREAD/Insufficient; exactly.60 passes. Evaluate **after** IQR, never before; n<8 gets no statistical removal. This is separate from confidence spread cap.

Display min–max for n3–4; P10–P90 for n>=5. **WIDE_SPREAD cap uses exact(P90−P10)/median >0.30 for every valid n including3–4**; compute these internal quantiles even when display MIN_MAX. Exactly.30 no cap. Q1 is now explicitly CTO-decided, not claimed prior ruling. Rationale: stable definition independent of display choice; n3–4 already capLOW49, so width cap79 cannot increase or decrease that LOW result, but reason remains informative.

## 7. Exact stats/verdict and output rounding
All medians, quantiles, IQR fences, spread ratios, diffs and decisions remain exact rationals/decimal arithmetic. Persist exact reduced numerator/denominator or lossless decimal plus observation refs for recomputation; never replace median with rounded Money. No float threshold comparison.

`d=(asking−median)/median` unrounded: **Fair iff−0.15<=d<=+0.10 inclusive**; High d>.10; Unusually Low d<−.15 with seller/condition/PTA caution, not scam accusation. Internal ratio d vs public `diff_percent=d` is a fraction for Intl percent (0.0882 means8.82%); legacy flat QA fixtures express percent points100*d and require DTO adapter, per API v0.5. At final Money output round **half-even to integer paisa**: range bounds,median,diff_absolute_minor and `fair_band_low=median×.85`, `fair_band_high=median×1.10`. Fair-band values are labels, never rounded thresholds for verdict. UI PKR Intl may render currency decimal precision but cannot alter underlying verdict. Percentage display precision separate from logic; keep unrounded rational/internal and full numeric percentage DTO before UI formatting.

## 8. Confidence (Q3/Q17/Q18/Q19)
Only after gates. S=min(n/10,1),D=min(d/3,1),R=mean(1−.5×fractional_age_days/window_days),Q=mean(match quality1 exact SKU or.9 independently verified equivalent attributes). Critical unknown not discounted into admission.

`C_raw=100*(.30S+.25D+.25R+.20Q)` exact/unrounded. **Round half-even once to integer, THEN apply all caps with min, THEN band**.78.5→78;49.5→50 then n3–4 cap→49. No intermediate rounding. n<5 OR d<2 cap49; P90/P10 width>.30 OR any match quality<1 cap79; unconfirmed target PTA cap49. LOW0–49,MEDIUM50–79,HIGH80–100. No arbitrary low-score insufficiency floor. Reason SINGLE_SOURCE for d=1 (ultimate owner even across domains), FEW_COMPARABLES for n3–4, WIDE_SPREAD for exact percentile width>.30, ATTRIBUTE_MATCH_NOT_SKU for quality<1, PTA_UNCONFIRMED for split. ASKING_NOT_SOLD_PRICES always disclosed. Direct scorer tests n5/d1 remain useful cap tests, but integrated seller-dedup cannot manufacture5 effective offers from one owner.

Unknown target PTA doesn't block; Approved/Non-PTA branches separate, each gates independently. n2+n2 insufficient; qualifying branches capped49 LOW, no global median/verdict. Split summary=min(passing branch capped scores); one passing branch→that score; failed branch contributes no null-as-zero. `indicative=true` only when a LOW **price verdict** exists; NO_ASKING_PRICE+LOW and PTA_SELECTION_REQUIRED have indicative=false,low_confidence_modifier=true. Confirm PTA before global verdict; retain separate labelled branch evidence.
