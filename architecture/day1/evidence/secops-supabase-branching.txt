Branching takes this further, adding isolated preview environments for each pull request.</p>
<p>Use branching to safely experiment with changes to your Supabase project.</p>
<p>Supabase branches create separate environments that spin off from your base project. You can use these branching environments to create and test changes like new configurations, database schemas, or features without affecting your production setup. When you&#x27;re ready to ship your changes, merge your branch to update your production instance with the new changes.</p>
<h2 id="how-branching-works" class="group scroll-mt-24">How branching works<a href="#how-branching-works" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<ul>
<li><strong>Separate Environments</strong>: Each branch is a separate environment with its own Supabase instance and API credentials.</li>
<li><strong>Preview Branches</strong>: Preview branches are ephemeral and best suited for focused testing. They are automatically deleted when a PR is merged or closed.</li>
<li><strong>Persistent Branches</strong>: Persistent branches are long-lived and recommended for environments like staging, QA, or development. They aren&#x27;t automatically paused or deleted due to inactivity or when a PR is merged or closed.</li>
<li><strong>Managing Branches</strong>: You can create, review, and merge branches either automatically via our <a href="/docs/guides/deployment/branching/github-integration" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">GitHub integration</a> or directly <a href="/docs/guides/deployment/branching/dashboard" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">through the Supabase Dashboard</a> (currently in beta). All branches show up in the branches page in the dashboard, regardless of how they were created.</li>
<li><strong>Cloned from your base project</strong>: Each new branch is created as a clone of your base project. It starts with that project&#x27;s Edge Functions deployed and the configuration set.</li>
<li><strong>Data-less by default</strong>: By default, new branches do not start with any data or storage objects from your base project. This is meant to better protect your sensitive production data. To start your branches with data, you can use a <a href="/docs/guides/deployment/branching/github-integration#seeding" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">seed file</a> if using the GitHub integration, or the <a href="/docs/guides/deployment/branching/dashboard#include-production-data" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">Include data</a> option if you create the branch from the Supabase Dashboard.</li>
</ul>
<h2 id="what-a-new-branch-starts-with" class="group scroll-mt-24">What a new branch starts with<a href="#what-a-new-branch-starts-with" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<p>Whether you create a branch from a pull request or from the Supabase Dashboard, Supabase creates a project with default settings then copies these settings from your base project:</p>
<ul>
<li>Postgres settings</li>
<li>Connection pooler settings</li>
<li>Auth, Data API, Realtime, and Storage settings</li>
<li>SSL enforcement</li>
<li>Network restrictions, when your base project has them</li>
<li>Deployed Edge Functions</li>
</ul>
<p>Auth secrets, such as OAuth provider secrets and SMTP passwords, get placeholder values instead. Set the real values with <a href="/docs/guides/deployment/branching/configuration#managing-secrets-for-branches" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">branch secrets</a>. Supabase also turns on Database Webhooks for every branch.</p>
<p>The database schema isn&#x27;t cloned. A GitHub-connected branch builds it from the <a href="/docs/guides/deployment/branching/github-integration#migrations" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">migrations in your repository</a>. A dashboard branch builds it from your <a href="/docs/guides/deployment/branching/dashboard#where-a-dashboard-branch-gets-its-schema" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">base project&#x27;s migration history</a>. The branch is ready when the settings, the schema, and the Edge Functions are all in place.</p>
<h2 id="deploying-to-production" class="group scroll-mt-24">Deploying to production<a href="#deploying-to-production" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<p>When you merge any branch into your base project, Supabase automatically runs a deployment workflow to deploy your changes to production. The deployment workflow is expressed as a Directed Acyclic Graph where each node represents one of the following deployment steps.</p>
<ol>
<li><strong>Clone</strong> - Checks out your repository at the specified git branch (optional for <a href="/docs/guides/deployment/branching/dashboard" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">Branching via Dashboard</a>)</li>
<li><strong>Pull</strong> - Retrieves database migrations from your base project (also initialises the migration history table when Branching via Dashboard)</li>
<li><strong>Health</strong> - Waits up to 2 minutes for all Supabase services on your branch to be running and healthy, including Auth, API, Database, Storage, and Realtime</li>
<li><strong>Configure</strong> - Updates service configurations based on your config.toml file (only available for <a href="/docs/guides/deployment/branching/github-integration" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">Branching via GitHub</a>)</li>
<li><strong>Migrate</strong> - Applies pending database migrations and vault secrets to your branch</li>
<li><strong>Seed</strong> - Runs seed files to populate your branch with initial data (must be <a href="/docs/guides/deployment/branching/configuration#branch-configuration-with-remotes" class="underline transition underline-offset-2 decoration-inherit hover:decoration-foreground text-inherit hover:text-foreground">enabled in config.toml</a> for persistent branches)</li>
<li><strong>Deploy</strong> - Deploys any changed Edge Functions and updates function secrets</li>
</ol>
<p>If a parent deployment step fails, all dependent child steps are skipped. For instance, if your database migrations fail at step 5, our runner doesn&#x27;t seed your branch because step 6 is skipped. If you are using GitHub integration, the same deployment workflow runs on every commit pushed to your git branch. To check each step&#x27;s status in the Supabase Dashboard, see <a href="/docs/guides/deployment/branching/troubleshooting#monitoring-deployments" class="underline transition underline-offset-2
