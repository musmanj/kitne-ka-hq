  The engine's code comments mark several rules as "CTO-confirmed v0" that are **not in the methodology/API docs I read**: half-even rounding, a 5-minute future-timestamp tolerance with a new `INVALID_TIMESTAMP` exclusion, `GEO_SPREAD` reason, the spread cap always using P90−P10 (even for MIN_MAX), and `NEAR_EXPIRY` at ≤ 20% remaining. QA has not seen the CTO decision record. CTO should confirm these and add them to methodology v0.x. They would close Q1/Q2/Q10 in favour of the code.
- **QA probe (real, limited).** At 00:45 PKT I ran a throw-away Vitest probe (`tools/qa-probe.test.ts`) against a **copy** of `app/` in `/tmp`; I did not modify `app/`. The Engineer's own suite on that copy: 6 files, 193 tests passed. Probe observations on that snapshot (code may since have changed):
  - Matches vectors: RNG-01 quantiles (98,800 / 105,200 / 102,000), VER-boundary verdicts at −15%/+10% incl. paisa, CON-01 = 82, CON-08 = 80.
  - **Mismatch vs PRD §6 (likely S2 defects):** `normalisePkr('1.2L')`, `('PKR 125000/-')` and `('₨ 120,000')` → `NOT_A_NUMBER`. The PRD requires "1.2L" and "Rs./PKR/₨".
  - **CON-10 tie:** `scoreConfidence` uses float `Math.round`. For C_raw = 78.5 exactly it returned **78** (float error makes it 78.4999…). Half-up would give 79. This is real evidence for Q3.
  - `'1.2'` → 120 PKR and `'500'` → 500 PKR are accepted with no flag (Q13/Q14); `'۱,۲۵,۰۰۰'` and `'$500'` → `NOT_A_NUMBER` (Q11; USD should probably map to a distinct "unsupported currency" outcome).
- Money is **integer paisa** (PKR × 100). Compare thresholds with exact rationals or integer cross-multiplication, for example FAIR iff `-15*M <= 100*(A-M) <= 10*M`. Do not compare floats. Where a value is not a whole number, `diff_percent` is given as a `"num/den"` string, with `diff_percent_approx` for display.
- Quantile = linear interpolation, `h=(n-1)p` over the ascending sorted values, 0-indexed. The median uses the same rule (p=0.5).
- In range/verdict vectors every listed observation is already admitted unless the case says otherwise (fresh, same variant/condition/PTA, distinct sellers). Confidence vectors list `n`, `d`, `ages_days` and `match_quality` directly.
- Suggested Vitest pattern: `describe.each(vectors.filter(v => v.expected?.status !== 'TBD - needs CTO decision'))`, and `it.todo` for TBD vectors so they stay visible.
- `PTA-*`, `CLS-*` and `PRE-01` are integration/contract-level (envelope, HTTP). The rest are pure-unit.
